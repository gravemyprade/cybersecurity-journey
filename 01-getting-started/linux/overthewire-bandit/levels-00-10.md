# OverTheWire Bandit — рівні 0–10

Гра: [OverTheWire Bandit](https://overthewire.org/wargames/bandit/)
Середовище: Ubuntu у VirtualBox, підключення по SSH
Дата: 27.09.2026

> Паролі від рівнів не публікуються за правилами OverTheWire. Замість них — `<пароль>`.

Підключення до кожного рівня однакове, змінюється лише номер користувача:

```bash
ssh banditN@bandit.labs.overthewire.org -p 2220
```

---

## Level 0 — підключення по SSH

**Завдання:** підключитися до сервера гри: хост `bandit.labs.overthewire.org`, порт `2220`, користувач і пароль `bandit0`.

```bash
ssh bandit0@bandit.labs.overthewire.org -p 2220
```

- `bandit0@...` — ім'я користувача і адреса сервера;
- `-p 2220` — нестандартний порт (за замовчуванням SSH працює на 22).

Пароль під час введення не відображається — це нормальна поведінка терміналу.

**Що вивчив:** як підключатися до віддаленого Linux-сервера; `Permission denied` при вході = неправильний пароль; у терміналі копіювати Ctrl+Shift+C, вставляти Ctrl+Shift+V.

## Level 0 → 1 — прочитати файл

**Завдання:** пароль у файлі `readme` у домашній папці.

```bash
man ls        # розібрався, що робить команда
ls            # побачив файл readme
cat readme    # вивів вміст
```

**Що вивчив:** `man` — вбудована документація (вихід — `q`); `ls` — вміст папки; `cat` — вивести файл.

---

## Level 1 → 2 — файл з назвою `-`

**Завдання:** пароль у файлі, який називається просто `-`.

**Хід думок:**
1. `ls` показав файл `-`.
2. `cat /-` — `No such file`: `/` на початку означає корінь системи, а не поточну папку.
3. Рішення — вказати шлях від поточної папки:

```bash
cat ./-
```

**Що вивчив:**
- `.` — поточна папка, `..` — на рівень вище, `~` — домашня, `/` на початку — корінь системи.
- Якщо назва починається з дефіса, команда сприймає її як опцію. `./` перетворює назву на шлях.
- Лапки тут не допомагають: оболонка прибирає їх, і `cat` усе одно отримує `-`.

---

## Level 2 → 3 — пробіли й дефіси в назві

**Завдання:** пароль у файлі `--spaces in this filename--`.

**Хід думок:**
1. Застосував правило з минулого рівня: назва починається з дефісів, отже потрібен `./`. Очікував, що цього вистачить.
2. `ls ./--spaces in this filename--` — але назва розпалася на 4 окремі «файли»: `./--spaces`, `in`, `this`, `filename--`. Тобто `./` вирішив проблему з дефісом, але не з пробілами: термінал ріже текст по пробілах ще до того, як команда його отримає.
3. Набрав початок назви і натиснув **Tab** — термінал дописав назву, поставивши `\` перед кожним пробілом:

```bash
cat ./--spaces\ in\ this\ filename--
# те саме через лапки:
cat "./--spaces in this filename--"
```

**Що вивчив:**
- Дефіс на початку назви → `./`.
- Пробіли й спецсимволи → лапки `"..."` або `\` перед кожним символом.
- Tab — автодоповнення, економить час і захищає від опечаток.

## Level 3 → 4 — прихований файл

**Завдання:** пароль у прихованому файлі в папці `inhere`.

```bash
ls -la inhere
# ...Hiding-From-You
cd inhere
cat ./...Hiding-From-You
```

**Що вивчив:**
- Файли, що починаються з крапки, приховані; звичайний `ls` їх не показує, `ls -a` / `ls -la` — показує.
- Синім у `ls` позначені папки.
- Спробував `find` по всій `/home` і отримав купу `Permission denied`: до чужих домашніх папок доступу немає.

---

## Level 4 → 5 — єдиний текстовий файл

**Завдання:** пароль в єдиному human-readable файлі в `inhere`, де лежать `-file00` … `-file09`.

**Хід думок:** щоб не відкривати файли навмання, перевірив тип усіх файлів одразу:

```bash
cd inhere
file ./*
# ./-file07: ASCII text   ← єдиний текстовий, решта data
cat ./-file07
```

**Що вивчив:** `file` визначає тип файлу; `*` — усі файли в папці. Так не довелося відкривати бінарні файли навмання (після `cat` бінарника термінал можна відновити командою `reset`).

---

## Level 5 → 6 — пошук за властивостями

**Завдання:** у `inhere` 20 папок `maybehere00`–`19`. Потрібен файл, який: human-readable, 1033 байти, не виконуваний.

**Хід думок:**
1. `file ./*` показав 20 папок з файлами всередині — перевіряти вручну занадто довго, потрібен `find`.
2. Думав, що умову можна написати просто словом: `find ./* size 1033c`. Але `find` вивів усі файли підряд, а `size` і `1033c` сприйняв як назви папок. Умови `find` — це опції, вони пишуться з дефісом.
3. З дефісом — один результат:

```bash
find . -size 1033c
# ./maybehere07/.file2
find . -size 1033c ! -executable   # перевірка з усіма умовами — той самий файл
cat ./maybehere07/.file2
```

**Помилка, на якій спіткнувся:** уже перебуваючи в `maybehere07`, писав шлях `./maybehere07/.file2` — відносний шлях рахується від поточної папки.

**Що вивчив:**
- `find . -size 1033c` — пошук за розміром у всіх вкладених папках; `c` = байти.
- Умови `find` пишуться з дефісом і комбінуються; `!` — заперечення.
- Перш ніж писати відносний шлях — дивитися, де я (`pwd` або запрошення терміналу).
- `cd ..` — вище, `cd -` — попередня папка, `cd ~` — домашня.

---

## Level 6 → 7 — пошук по всьому серверу

**Завдання:** файл «десь на сервері», власник `bandit7`, група `bandit6`, розмір 33 байти.

**Хід думок:**
1. Домашня папка порожня, а `/home` — лише домашні папки користувачів. Ходити по серверу вручну — безнадійно.
2. Вирішив, що «десь на сервері» — це серед папок користувачів, і шукав у `/home`: `find /home -size 33c -group bandit6 -user bandit7`. Умови були правильні, але результат — лише `Permission denied`. `/home` — це одна папка сервера, а весь сервер починається з кореня `/`.
3. Пошук від кореня знайшов файл серед сотень помилок. Щоб прибрати шум, помилки перенаправляються в «чорну діру»:

```bash
find / -user bandit7 -group bandit6 -size 33c 2>/dev/null
# /var/lib/dpkg/info/bandit7.password
cat /var/lib/dpkg/info/bandit7.password
```

**Що вивчив:**
- `/` — весь сервер; `/home` — лише одна папка всередині нього.
- `-user`, `-group` — пошук за власником і групою (їх видно в 3-й і 4-й колонках `ls -la`).
- `2>/dev/null`: `2` — канал помилок, `>` — перенаправити, `/dev/null` — все, що туди потрапляє, зникає.
- Абсолютний шлях (з `/`) працює звідки завгодно.

## Level 7 → 8 — пошук рядка у файлі

**Завдання:** пароль у `data.txt` поруч зі словом `millionth`.

```bash
cat data.txt              # тисячі рядків — очима не знайти, Ctrl+C
grep millionth data.txt   # один рядок: millionth  <пароль>
```

**Що вивчив:** `grep` шукає текст усередині файлів і виводить **весь рядок** зі збігом, тому пароль, що стояв у тому ж рядку, опинився на екрані. Лише сам збіг виводить `grep -o`. У SOC так шукають IP-адреси та події в логах.

---

## Level 8 → 9 — унікальний рядок

**Завдання:** пароль — єдиний рядок у `data.txt`, який зустрічається лише один раз.

**Хід думок:**
1. `uniq -u` показує рядки без повторів, але порівнює лише **сусідні** рядки.
2. Тому спершу `sort` — він зсуває однакові рядки разом.
3. Результат `sort` передав у `uniq` через pipe (`|`, на клавіатурі Shift + `\`):

```bash
sort data.txt | uniq -u
```

Спершу уявляв ланцюжок як `sort | uniq data.txt`, тобто з файлом наприкінці. Але файл має читати перша команда, а `uniq` отримує дані вже з pipe.

**Що вивчив:** `|` передає вивід однієї команди на вхід іншої. Зв'язка `sort | uniq` — основа аналізу логів (наприклад, `sort | uniq -c | sort -nr` — найчастіші рядки зверху).

## Level 9 → 10 — текст у бінарному файлі

**Завдання:** пароль в одному з небагатьох читабельних рядків у `data.txt`, перед ним кілька знаків `=`.

**Хід думок:**
1. Спершу застосував ланцюжок з минулого рівня: `sort data.txt | grep =`. Не спрацювало: `sort` лише переставляє рядки, а бінарне сміття лишається сміттям.
2. Потрібна команда, що витягує з бінарного файлу лише читабельний текст — `strings`.

```bash
strings data.txt | grep =    # багато шуму через випадкові '='
strings data.txt | grep ==   # лише потрібні рядки: "========== the / password / is / <пароль>"
```

**Що вивчив:**
- Усі файли — це байти; текстові відповідають буквам за таблицею кодування, бінарні призначені для програм.
- `strings` показує лише читабельні шматки. У SOC — одна з перших дій з підозрілим файлом, щоб побачити IP, посилання, команди, не запускаючи його.
- Чим точніша умова пошуку, тим менше шуму.

---

## Level 10 → 11 — base64

**Завдання:** пароль у `data.txt`, закодований у base64.

```bash
cat data.txt          # рядок з літер, цифр і '==' в кінці
man base64
base64 -d data.txt    # The password is <пароль>
```

**Що вивчив:**
- Base64 — **кодування, а не шифрування**: ключа немає, розкодувати може будь-хто.
- Зловмисники використовують base64 для маскування команд (наприклад, `powershell -enc ...`), тому в SOC такі рядки декодують одразу.

## Команди, вивчені за рівні 0–10

- `ssh user@host -p порт` — підключення до сервера; `exit` — вийти
- `man команда` — документація (`q` — вихід, `/` — пошук)
- `pwd` — де я; `ls`, `ls -la` — вміст папки, зокрема приховані файли
- `cd папка`, `cd ..`, `cd -`, `cd ~` — переходи між папками
- `cat файл`, `cat ./-файл`, `cat "назва з пробілами"` — читання файлів
- `file ./*` — тип усіх файлів у папці
- `find . -size 1033c ! -executable` — пошук за властивостями
- `find / -user X -group Y -size 33c 2>/dev/null` — пошук по всьому серверу без помилок
- `grep слово файл` — рядки з текстом
- `sort файл | uniq -u` — унікальні рядки
- `strings файл | grep ==` — текст із бінарного файлу
- `base64 -d файл` — розкодувати base64

## Головні висновки

- У терміналі важить кожен символ: пробіл, дефіс, крапка, `/`.
- Відносний шлях рахується від поточної папки — завжди перевіряти, де я.
- Спершу подивитися масштаб (`ls`, `file`, `cat` + Ctrl+C), потім обирати інструмент.
- Точніші умови пошуку = менше шуму.
