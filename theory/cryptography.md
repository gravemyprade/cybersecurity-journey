# Конспект — Криптографія та PKI

> Шифрування, хешування, підписи, TLS, PKI, квантова загроза (Fortinet FCF). Базовий словник — у [[cybersecurity-fundamentals]].

---

## Основи

**Криптографія** — захист інформації перетворенням даних. Три задачі: **конфіденційність** (шифрування), **цілісність** (хеш), **автентичність** (підписи).

- **Plaintext** → **Ciphertext** — відкритий текст → шифротекст.
- **Cipher (шифр)** — *алгоритм* перетворення. **Key (ключ)** — *секретне число*, що його налаштовує. Алгоритм публічний, ключ — секрет.

### Симетричне vs асиметричне
- **Симетричне** — **один** спільний ключ шифрує й розшифровує. Швидке. Проблема — безпечно **передати ключ**.
- **Асиметричне** — **пара** ключів: **публічний** (роздаєш, ним замикають тобі) + **приватний** (тільки в тебе, ним відмикаєш). Що один замкнув — лише інший відімкне. Повільне, але вирішує передачу ключа. Приватний **генерується в тебе й нікуди не передається**.
- **На практиці — разом:** асиметрикою безпечно домовляються про симетричний ключ, далі симетрикою шифрують дані (так працюють TLS, VPN, месенджери).

### Block vs Stream
- **Block** — шифрує шматками фіксованого розміру (AES = **128 біт = 16 байт**), останній добиває **padding**.
- **Stream** — з ключа генерується довгий **keystream**, що XOR-иться з даними **побайтово**. Для реального часу (голос/відео).

### Типи шифрів (методи)
- **Substitution** — заміна символів (Цезар). **Transposition** — перестановка порядку (rail fence). **OTP (one-time pad)** — випадковий ключ довжини тексту, одноразовий: теоретично незламний, але непрактичний.

### Алгоритми
| Тип | Алгоритми |
|---|---|
| Симетричні | **AES** (стандарт), ChaCha20 (stream), IDEA, Blowfish/Twofish · застарілі: DES/3DES, RC4 |
| Асиметричні | **RSA** (шифр+підпис), **ECC** (коротший ключ), **Diffie-Hellman** (обмін ключами), **DSA** (тільки підписи) |

## Хешування

**Хеш** — однобічна функція: з даних будь-якого розміру робить **відбиток фіксованої довжини**. **Без ключа, необоротний** — назад не відновити, тільки звірити.

Три властивості: **фіксована довжина** · **унікальний для кожного входу** (зміна біта → інший хеш = видно підробку) · **one-way**.

- **Collision (колізія)** — два різні входи з однаковим хешем. Так зламали **MD5, SHA-1** → не використовувати. Брати **SHA-256/SHA-3**.
- **Salt** — випадкове значення, додане до пароля перед хешуванням: вбиває райдужні таблиці, однакові паролі дають різні хеші.
- **Key stretching** — хешувати тисячі разів, щоб було **повільно** (брутфорс дорогий): **bcrypt, PBKDF2, Argon2**.

**Шифротекст vs хеш:** шифротекст **оборотний** (ключем вертаєш назад, мета — приховати й прочитати); хеш **необоротний** (мета — звірити, напр. паролі зберігають хешем, не оригіналом).

## Цифрові підписи

Дзеркало шифрування: **підписуєш своїм ПРИВАТНИМ ключем, перевіряють твоїм ПУБЛІЧНИМ.**

Процес: хешуєш документ → шифруєш хеш приватним ключем = **підпис** → чіпляєш до даних. Отримувач сам рахує хеш + розшифровує підпис публічним → звіряє.

Дає: **Authentication** (хто підписав) + **Integrity** (не змінено) + **Non-repudiation** (не відмовишся). **НЕ дає конфіденційності** — підпис нічого не ховає.

Де: HTTPS-сертифікати, оновлення ПЗ, Дія/КЕП, App Store, підписані листи (PGP), блокчейн.

## TLS / HTTPS

**TLS** (наступник мертвого SSL) — протокол захисту зв'язку, «S» у HTTPS. Дає конфіденційність + цілісність + автентичність.

**Handshake** (на старті):
1. Клієнт/сервер обирають версію + шифр.
2. Сервер шле **сертифікат** (публічний ключ + підпис CA).
3. Клієнт перевіряє сертифікат (ланцюг до довіреного кореня).
4. Домовляються про **симетричний ключ сесії** (клієнт шифрує його публічним ключем сервера, або Diffie-Hellman → forward secrecy).
5. Далі весь трафік шифрується швидкою **симетрикою** (AES).

**Версії:** TLS 1.2 (ще ок), **TLS 1.3** (найкращий: швидший, forward secrecy обов'язковий). SSL і TLS 1.0/1.1 — застарілі.

**Forward secrecy** — новий ключ на кожну сесію: крадіжка приватного ключа не розкриє старі записи.

> **VPN** — те саме на рівні всієї мережі: асиметрика (handshake) + симетрика (трафік) + хеш. Протоколи: WireGuard, OpenVPN, IPsec.

## PKI (Public Key Infrastructure)

Система довіри: дозволяє **вірити, що публічний ключ справді належить тому, хто каже** (бо ключ-число може згенерувати будь-хто).

**4 сутності:**
- **CA (Certificate Authority)** — видає й **підписує** сертифікати (якір довіри).
- **RA (Registration Authority)** — перевіряє особу заявника до видачі.
- **Directory Server** — зберігає/публікує сертифікати + списки відкликаних.
- **End Entity** — власник сертифіката (сайт, або ти в Дії).

**Ланцюг довіри:**
```
Root CA (вшитий у ОС/браузер, джерело довіри)
  → підписує Intermediate CA
    → підписує сертифікат сайту
```
Перевірка йде **знизу вгору**: сертифікат сайту ← проміжний ← корінь (якому вже довіряєш) → довіра.

**Сертифікат містить:** serial number, алгоритми, строк дії (Valid from/to), Issuer (хто підписав, CA), Subject (кому), публічний ключ, key usage, підпис CA.

**Життєвий цикл:** видача (через **CSR** — запит із публічним ключем) → строк дії → **відкликання** (CRL / OCSP, якщо ключ скомпрометовано).

> **🔒 ≠ безпечно.** Фішери теж мають валідні сертифікати на свої домени. Замок = «зашифровано + це той домен», **не** «це чесний сайт». Дивитись треба на сам домен (Subject).

## Атаки на крипту й реальні витоки

- **Brute force** — перебір ключів/паролів. Захист — довжина + складність.
- **Frequency analysis** — частотний аналіз (класичні substitution).
- **Collision / Birthday attack** — знайти колізію хешу. Через **парадокс днів народження** колізію знаходять за ~`2^(n/2)`, не `2^n` → тому стійкість до колізій = **половина** довжини хешу (SHA-256 → 128 біт). Так упали MD5/SHA-1.
- **Side-channel** — витік через час/енергію/звук (не математика).

> **Чому паролі «витікають», хоч хеш необоротний:** ламають не математику, а оточення — погане хешування (MD5 без salt), слабкі паролі, plaintext-зберігання, вхід через SQL-injection/фішинг/конфіг, **реюз паролів** (credential stuffing). Правило: AES ніхто не розгадує — обходять стіну через двері/людей.

**Don't roll your own crypto** — не писати свій шифр, брати перевірені (AES, TLS-бібліотеки).

## Квантова загроза та PQC

**Quantum computing (загроза):** кубіт у **суперпозиції** (0 і 1 разом) → для певних задач квант різко швидший.
- **Shor** → факторизація → **ЛАМАЄ асиметрику** (RSA, ECC, Diffie-Hellman).
- **Grover** → лише **ослаблює вдвічі** симетрику й хеш.

| Що робить квант | Клас | Що робити |
|---|---|---|
| **ЛАМАЄ** | RSA / ECC / DH (асиметрика) | **міняти алгоритм** (PQC) |
| ослаблює | AES (симетрика) | брати **AES-256** |
| ослаблює | SHA (хеш) | брати **SHA-256+** |

> **«Harvest now, decrypt later»** — ворог записує зашифрований трафік **сьогодні**, щоб розшифрувати квантом **згодом**. Тому довго-чутливі дані під загрозою вже зараз.

**Дві відповіді** (не плутати):
- **PQC (Post-Quantum Cryptography)** — **математична**, софтверна, на звичайних комп'ютерах. **Мейнстрім.** Стандарти NIST (2024): **Kyber/ML-KEM** (ключі), **Dilithium/ML-DSA** (підписи), + SPHINCS+, FALCON. Підходи: lattice-based (головний), hash-, code-, multivariate-based.
- **QKD (Quantum Cryptography)** — **фізична**: передає ключ так, що підслух **виявляється** (вимір змінює квантовий стан) і ключ **не скопіювати** (no-cloning). Незламна теоретично, але **нішева** (треба спец-залізо).

Плюс **crypto-agility** (легко міняти алгоритми) + **hybrid** (старий+новий разом на час переходу).
