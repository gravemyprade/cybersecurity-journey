# Конспект — Захищена мережа

> Периметр, zero-trust, файрволи, сегментація, захист протоколів, L2-атаки, DoS, sandbox, OT (Fortinet FCF). Базовий словник — у [[cybersecurity-fundamentals]], криптографія — у [[cryptography]], види атак — у [[threat-landscape]].

---

## Дві моделі мережевої безпеки

### Secure Perimeter Model («trust but verify»)
Замок із ровом: один рубіж на межі, усередині — **зона неявної довіри** (implicit trust). Перевірка лише при початковому вході; потрапив усередину — рухаєшся вільно.
- **Слабке місце — lateral movement:** зламали один хост → ворог гуляє по пласкій мережі без перешкод.
- Працює, поки є чіткий кордон «всередині / зовні».

### Чому периметр «помер» — business transformation
Бізнес розповзся за межі будівлі, і attack surface різко виріс:
- **Cloud (private/public)** — дані й апки не у своїй мережі;
- **Remote work** — працюють із недовірених мереж;
- **BYOD** — особисті неконтрольовані пристрої;
- **IoT** — багато пристроїв зі слабкою прошивкою.

Кордон розмився → «довіра за фактом перебування в мережі» стала безглуздою.

### Zero-Trust Model («never trust, always verify»)
Довіри за замовчуванням нема; вона **обчислюється щоразу** з доказів. Немає довіреної зони.

**Формула:** `Trust = Identity + Context`
- **Identity** — хто ти (MFA, сертифікат пристрою);
- **Context** — обставини: час, геолокація, стан пристрою, ризик-скор.

**Три принципи:**
1. **Never trust, always verify** — перевіряти кожен запит. Складові: **Authentication** (хто ти) + **Authorization** (що тобі можна) — різні кроки.
2. **Least privilege** — давати рівно стільки доступу, скільки треба.
3. **Assume breach** — проєктувати так, ніби ворог уже всередині; зменшувати attack surface, обмежувати радіус вибуху.

> **Гібрид на практиці:** periметр і zero-trust співіснують, бо міграція повільна. Напрямок руху — від периметра до zero-trust. Периметр лишається як **один із шарів** (defense in depth), а відмирає саме «довіра за присутністю».

## Never Trust — фактори довіри

**Identification:**
- **MFA** — кілька факторів: щось знаєш (пароль) + щось маєш (токен/телефон) + щось ти є (біометрія). Мінімум два з різних категорій.

**Context-Based Aspects:**
- **Time/date** — чи звичний час входу;
- **Geolocation** — звідки (impossible travel → блок);
- **Security posture** — стан пристрою: ОС, патчі, антивірус, не зламаний.

---

## Least Privilege — методи реалізації
- **PAM (Privileged Access Management)** — керування привілейованими акаунтами: сховище паролів, видача прав **тимчасово й під задачу** (just-in-time), логування привілейованих сесій.
- **Define the protect surface** — замість гнатися за всім attack surface, визначити найцінніше (**DAAS**: Data, Applications, Assets, Services) і щільно боронити його.
- **Kipling method** — для кожного правила доступу відповісти на 6 питань: **Who, What, When, Where, Why, How**. Доступ дають, лише коли є чітка відповідь на всі шість.

## Assume Breach — реалізація
- **Microsegmentation** — мережу ділять на мікросегменти, **файрвол навколо кожного сервісу** (Web/Apps/DB). Зламаний хост замкнений у своєму сегменті → обмеження blast radius (запобігання «зараженню»).

## Інші методи zero-trust
- **RBAC (Role-Based Access Control)** — права прив'язані до **ролі**, не до особи. Нова людина → роль; пішла → роль забрали.
- **Endpoint agent** — програма на пристрої, що доповідає стан (ОС, patch level, встановлене ПЗ) — живить security posture.

## Фільтрація трафіку через периметр (драбина OSI)
Периметр фільтрує на різних рівнях; вгору по стеку — більше контексту, точніше рішення, але дорожче.

| Рівень OSI | Чим фільтрує | Приклад |
|---|---|---|
| **L2 Data Link** | MAC-адреса | MAC-фільтрація: known MAC → пропуск, unknown → блок |
| **L3 Network** | IP, протокол | ACL, NAT-filtering |
| **L4 Transport** | порти, 5-tuple, стан з'єднання | stateful firewall |
| **L7 Application** | вміст, команди протоколу | ALG / проксі |

- **5-tuple** = src IP + dst IP + src port + dst port + protocol.
- **Stateful** = 5-tuple **+ connection state**: тримає таблицю активних з'єднань, пускає відповідь на власний запит автоматично, невитребуване вхідне ріже. Захист односторонній (ловить вхідне непрохане, вихідне ініційоване пропускає).
- **NAT filtering** — побічний захист NAT: внутрішні хости ззовні не видно; вхідне без запису в таблиці трансляцій дропається. Не замінює файрвол (вмісту не бачить, вихідне C2-з'єднання випустить).
- **ALG (Application Layer Gateway)** — легітимний MITM: розриває з'єднання на себе, бачить команди протоколу, відкриває динамічні порти (FTP/SIP) лише на час сесії.

## Еволюція файрволів

| Покоління | Що додає | Рівень |
|---|---|---|
| **1. Packet filter / stateless** | правила по 5-tuple, без пам'яті | L3/L4 |
| **2. Stateful** | + таблиця з'єднань (connection state) | L4 |
| **3. Third-generation** | + інспекція вмісту, розуміння протоколів застосунків + вбудовані AV/antispam/IPS/VPN | L7 |
| **4. NGFW** | + DPI, application-awareness, IPS, підтяжка threat intelligence, sandbox | L7 + інтелект |

**Firewall policies:**
- **Explicit** — правила, прописані вручну;
- **Implicit** — неявний `deny any` у кінці: що явно не дозволено — заблоковано.

**NGFW — три лінії оборони** (аналогія аеропорту):
1. правила/стан (перевірка талона);
2. DPI + IPS + application control (рентген вмісту);
3. sandbox + threat intelligence + поведінковий аналіз (проти zero-day).

### DPI (Deep Packet Inspection) — алгоритм
```
1. Reassembly — зібрати пакети в ціле повідомлення
2. Classify   — упізнати протокол/застосунок за структурою (не портом)
3. Inspect    — прогнати payload через сигнатури / правила / AV
4. Decide     — allow / drop / alert
```
Методи: **signature matching** (ловить відоме), **protocol identification** (упізнає апку за почерком незалежно від порту), **protocol decoding / anomaly**.
> **Обмеження:** на зашифрованому (TLS) трафіку DPI сліпий без **TLS-interception** (розшифрувати → інспектувати → зашифрувати назад = легітимний MITM). DPI дорогий по CPU.

### Як файрвол працює фізично
- **Choke point:** стоїть inline в єдиному горлі; трафік змушений іти через нього (шлюз за замовчуванням + default route). Має ≥2 інтерфейси (inside/outside).
- Бачить **лише те, що його перетинає** — north-south (вхід/вихід). Внутрішній east-west трафік повз периметр не йде → потребує сегментації.
- **Форми:** hardware appliance · software/host-based (iptables, Windows Firewall) · virtual/cloud. «Файрвол» — це роль/функція, не обов'язково коробка.
- **Покоління ≠ окремі коробки**, а рівні можливостей; старше включає молодші.
- **Defense in depth:** периметровий + host-based + сегментні + EDR + хмарні — шари закривають сліпі зони одне одного.

## Сегментація мережі

- **Underlay** — фізичні канали. **Overlay** — віртуальна мережа поверх (SD-WAN будує зашифровані overlay-тунелі = фактично VPN між майданчиками).
- **DMZ** — напів-довірена буферна зона на межі, куди ставлять публічно доступні сервіси (веб, пошта).
- **Bastion host** — укріплений **пристрій** на межі, єдина точка зовнішнього доступу (SSH/RDP/HTML). Дивиться назовні.
- **Jump box (jump server)** — внутрішній **пересадковий вузол** між периметром і сегментами. Дивиться всередину.
- Типовий ланцюг доступу: `інтернет → bastion → jump box → потрібний subnet`.
- **East-west трафік** (між сегментами) контролюють **мікросегментацією**, не периметром.

### SD-WAN vs SASE
- **SD-WAN** — розумна маршрутизація WAN по кількох каналах (broadband/LTE/MPLS), вибір найкращого шляху per-app. Про **швидкість/економію звʼязку**, не безпеку.
- **SASE (Secure Access Service Edge)** — SD-WAN + стек безпеки (ZTNA, firewall, SWG, CASB), доставлені **з хмари**. Користувач підключається до найближчої PoP, що перевіряє й маршрутизує. Охорона «їде за користувачем».

## Централізоване керування мережею
Керування багатьма пристроями з одного центру. Функції: **Configuring, Controlling, Operating, Diagnosing.**
- **SNMP** — класичний протокол моніторингу/керування (читає стан, змінює налаштування);
- **API** — сучасний програмований інтерфейс, основа автоматизації.

**Переваги:** широка видимість · простіше обслуговування · інтеграція пристроїв · прогнозування навантаження · менше ручної рутини.

### Data Fabric
Усі дані безпеки зводяться в єдине «полотно», поверх — **AI/ML**:
- **Automation** — рутинні реакції система виконує сама;
- **Recommendations** — підказки людині там, де не можна діяти автоматично.
- **ML** ловить аномалії (відхилення від норми), **AI** приймає рішення на їх основі.

### Fortinet Security Fabric (вендорська реалізація)
Складові: **Fabric Management Center** (end-to-end visibility) · **Zero Trust Access** · **FortiGuard** (threat intelligence) · **Open Ecosystem** (APIs, Fabric Connectors для стороннього ПЗ). Аналоги в інших вендорів: Cisco SecureX, Palo Alto Cortex.

## Атаки на L2 (комутатор)
L2-атаки **не віддалені** — потребують присутності в сегменті (фізичний порт, захоплений хост, Wi-Fi, інсайдер).

- **MAC flooding** — заливання світча фейковими source-MAC → переповнення **CAM-таблиці** → світч «ламається у відкриту» (fail open) і поводиться як **хаб** (шле на всі порти) → підслуховування чужого трафіку.
- **MAC spoofing** — підробка MAC для імперсонації пристрою (отруєння CAM) або обходу MAC-фільтрації.

**Захист (L2-hardening):**
- **Port security** — ліміт MAC на порт (перевищення → err-disabled): вбиває flooding; sticky-прив'язка MAC → проти spoofing;
- **DHCP snooping** — проти лівого DHCP;
- **Dynamic ARP Inspection (DAI)** — проти ARP-спуфінгу;
- **BPDU guard**, вимкнення невикористаних портів;
- **802.1X** — порт мертвий, поки пристрій не автентифікується (проти «воткнув чужий пристрій»).

## Захист протоколів
Незахищені протоколи (SMTP, HTTP, Telnet, FTP) ідуть **відкритим текстом** → сніфер читає. Захищені додають конфіденційність (+ цілісність/автентичність).

- **S/MIME** (email) — дві групи гарантій:
  - **Security** через цифровий підпис: Authentication + Non-repudiation + Data integrity (підписати **своїм приватним**, перевірити публічним);
  - **Confidentiality (end-to-end)** через шифрування: шифрувати **публічним ключем отримувача**, розшифрувати лише його приватним.
- **SSH** (віддалений доступ, порт 22) — цеглини: **Diffie-Hellman** (обмін ключами → forward secrecy) + симетрика (шифр сесії) + **MAC** (Message Authentication Code — цілісність кожного повідомлення; ≠ MAC-адреса). Застосування: tunneling, **SCP** (копіювання файлів), network management. Замінник Telnet.

## Sandbox (пісочниця)
Ізольоване віртуальне середовище, що **замикає дію застосунку** (відкриття файлу/браузера), обмежуючи доступ до **Network / Applications / Desktop Operations**. Застосування: захист у реальному часі (NGFW third line) + аналіз малварі.

**Три покоління:**
1. ізольована, сигнатури, сама по собі;
2. + інтеграція в мережу, автоматичний обмін загрозами;
3. + хмара + AI/ML + протидія **sandbox evasion** (імітує реального юзера, щоб малварь не «заснула»).

> **Обмеження:** просунута малварь визначає пісочницю й поводиться чемно, поки за нею дивляться (evasion).

## DoS-атаки
Б'ють по **Availability**. Два принципи: завалити **обсягом** або підсунути **кривий ввід**, що ламає обробку.

- **Flood** — засипати запитами (SYN/UDP/ICMP flood); DDoS = флуд із ботнету.
- **Ping of death** — некоректно великий ICMP-пакет → збій при зборці.
- **Teardrop** — фрагменти з перекритими offset → збій реасемблювання.
- **Permanent DoS (phlashing)** — псування прошивки → пристрій фізично неробочий.
- **Fork bomb** — процес нескінченно клонує себе → вичерпання ресурсів (**локальна** атака).
- **XMAS** — пакет з усіма TCP-прапорцями → плутає систему.
- **Smurf** — ICMP на broadcast із підробленим src=жертва → ампліфікація. **Fraggle** — те саме на UDP.

**Захист (атака → метод):**
- кривий пакет (Ping of death / XMAS / Teardrop) → **packet anomaly detection**;
- fork bomb → **ліміт процесів на користувача**;
- Smurf / Fraggle → роутер **не пересилає directed broadcast** (прибрати підсилювач);
- flood → **DoS-сенсори / network behavior analyzers**.

## OT Security (Operational Technology)

**OT vs IT:** IT працює з **даними** (збій = втрата даних); OT керує **фізичними процесами** (збій = аварія, зупинка, загроза життю). OT часто старе, непатчене, зі старими протоколами (Modbus, DNP3) без шифрування; «не вимкнути й не перезавантажити».

**Компоненти:**
- **ICS** — парасолька; **SCADA** (нагляд за розподіленими об'єктами), **PLC** (контролер обладнання);
- **IIoT** — промислові сенсори/пристрої;
- **HMI** — панель оператора (бачить і керує процесом);
- **RTU** — польові пристрої на віддалених об'єктах.

**Загрози:** Malware (є OT-заточена — Stuxnet, Triton, Industroyer) · Ransomware (зупинка виробництва) · Nation-State/APT (саботаж критичної інфраструктури) · Insider · Supply chain · Unauthorized remote access.

**Приклади:** University Hospital Düsseldorf (2020, ransomware, смерть пацієнтки) · Triton/Trisis (2017, атака на safety-системи заводу).

**Best practices:** Governance & risk management (інвентаризація активів) · Network & access control (**сегментація IT/OT — модель Purdue**, MFA на remote access, least privilege) · Monitoring & detection (OT-свідомі інструменти) · Incident response & recovery (не вимикати так, щоб спричинити аварію) · Workforce preparedness.
