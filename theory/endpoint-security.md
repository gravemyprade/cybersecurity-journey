# Конспект — Endpoint Security

> Захист кінцевих пристроїв: IoT/IIoT, загрози, hardening, firmware/TPM, шифрування, антивірус/EDR/XDR, DLP, керування. Базовий словник — у [[cybersecurity-fundamentals]], криптографія — у [[cryptography]], мережа — у [[secure-network]], доступ — у [[access-control]].

---

## Що таке endpoint і чому це мішень
**Endpoint** — будь-який кінцевий пристрій, що під'єднується до мережі: ПК, ноут, сервер, телефон, IoT. Це **найчастіша точка входу**, бо тут сидить людина (фішинг) і тут виконується код. Захист endpoint'а = остання лінія там, де мережеві контролі не дотягуються.

---

## IoT / IIoT

**IoT** — підключені пристрої, що збирають і шлють дані. Три рівні охоплення: **personal** (годинник, телефон, авто), **residential** (розумний дім — термостат, камера, розетка), **industrial**.

**IIoT (Industrial IoT)** — перетин **IT** (обмін даними) та **OT** (керування промисловим обладнанням): OT під'єднують до мереж/хмари. Дає **Automation / Efficiency / Data collection**, але OT **втрачає ізоляцію (air-gap)** → стає досяжним для атак (Triton/Industroyer). Відповідь — сегментація IT/OT (модель Purdue). Деталі OT — у [[secure-network]].

**Комунікація:** найпоширеніші — **Wi-Fi** і **Bluetooth** (також Zigbee, Z-Wave, LoRa, стільниковий).

**Проблема безпеки IoT:** багато дешевих пристроїв зі слабкою/непатченою прошивкою й дефолтними паролями → роздута attack surface. **Не підтримують встановлення традиційного захисного ПЗ** (антивірус/EDR на лампочку не поставиш).

### Захист IoT
Не можна захистити зсередини → захищають **навколо**:
1. **Identify** — упізнати пристрій;
2. **Register** — внести в інвентар/NAC;
3. **Невпізнані → в ізольовану мережу.**
Плюс: зміна дефолтних паролів, оновлення прошивки, **сегментація**, **NAC** (профілює й садить у свій VLAN). Правило: не можеш укріпити вузол — **обмеж його радіус** (assume breach).

## Загрози на endpoint'и

**Вектори зараження:**
- **Фішинг** — вкладення/лінк (найпоширеніший);
- **Шкідливий USB** (baiting — див. [[threat-landscape]]);
- **Drive-by download** — зараження з відвіданого сайту без дій;
- **Supply-chain** — отруєне оновлення довіреного ПЗ;
- **Брут RDP/SSH**, вкрадені креди.

**Persistence (закріплення)** — як малварь виживає після перезавантаження: автозапуск (registry run keys, startup), заплановані завдання, служби, rootkit, firmware-імплант (найглибше).

**Ботнети з endpoint'ів:** незахищений пристрій захоплюють → «зомбі» в **ботнеті** → використовують для атак на **локальні пристрої** (lateral movement) і на **зовнішні цілі** (масовий DDoS). Приклад — **Mirai** (2016, IoT-камери з дефолтними паролями). Наслідки: data loss, infrastructure attacks, privacy violations.

## Endpoint Hardening

### 1. Administrative Controls
Паролі (політика складності), **обмеження прав користувача** (не давати локального адміна без потреби), **PoLP** (least privilege).

### 2. Application control / allowlisting
**Allowlisting (whitelisting)** — запускається **лише дозволене** ПЗ, решта блокується (deny by default). Протилежність антивірусу (той блокує відоме погане). Дуже сильно, але трудомістко в підтримці. Той самий принцип implicit deny, що й в ACL.

### 3. OS & startup hardening
Прибрати зайві сервіси/порти/ПЗ, вимкнути непотрібні функції, закрити дефолтні дірки, налаштувати безпечні політики. Менше поверхні — менше атакувати.

### 4. Firmware & Boot
**Firmware** — код, що запускається **до ОС**. Firmware-малварь спрацьовує **раніше за антивірус** і **переживає перевстановлення ОС** (вона нижче рівнем) → дуже живуча.
- **UEFI vs BIOS:** UEFI вміє завантажувати **лише підписане ПЗ** — це **Secure Boot**: кожна ланка (UEFI → завантажувач → ядро) перевіряється **цифровим підписом** ([[cryptography]]) перед запуском. «Що не підписано — не вантажиться».
- **Measured Boot** — хеш кожної стадії завантаження записується в **TPM** для подальшої перевірки цілісності (attestation).
- **TPM (Trusted Platform Module)** — апаратний чип, **корінь довіри**: безпечно зберігає ключі/сертифікати, прив'язує (seal) ключ шифрування диска до стану завантаження. Змінили boot → TPM не віддасть ключ → диск не розшифрується.

### 5. Disk security & encryption
**Full Disk Encryption (FDE)** — вкрали ноут → дані не прочитають. **BitLocker** (Windows), **FileVault** (macOS), **LUKS** (Linux). Із **TPM** ключ видається лише при цілісному завантаженні.

### 6. Patch management
Оновлювати ОS, firmware, ПЗ. Між **розкриттям вразливості** і **накатом патчу** — вікно експозиції; більшість зламів іде через **відомі непатчені** дірки (n-day), не zero-day. Патчинг прибирає найлегші двері.

### 7. Device control
Контроль периферії: блокування **USB** / зовнішніх носіїв. Захищає і від шкідливих USB, і від ексфільтрації (перетин із DLP).

## Захисне ПЗ на endpoint'і

### Методи детекції (як антивірус/EPP ловлять)
| Метод | Як працює | Слабке місце |
|---|---|---|
| **Signature-based** | звірка з базою відомих сигнатур/хешів | не бачить нове/zero-day/поліморфне |
| **Heuristic** | статичний аналіз підозрілих ознак коду | хибні спрацьовування |
| **Behavioral** | стежить, що програма **робить** у рантаймі (API, файли, реєстр) | ловить невідоме по поведінці |
| **Sandboxing** | запуск підозрілого в ізоляції, спостереження | evasion (малварь «засинає») — див. [[secure-network]] |

### Інструменти (від простого до розумного)
- **Host-based firewall** — файрвол на самому пристрої (Windows Defender FW, iptables);
- **HIDS / HIPS** — host-based Intrusion Detection/Prevention: моніторить логи, цілісність файлів, процеси (виявлення / блокування) на хості, на відміну від мережевого IDS;
- **EPP (Endpoint Protection Platform)** — превентив: сигнатури + поведінка + host FW + device control в одному (антивірус++);
- **EDR (Endpoint Detection and Response)** — телеметрія з пристрою + виявлення підозрілого + **реакція** (ізолювати хост, вбити процес, відкотити зміни);
- **XDR (Extended DR)** — кореляція даних **поза межами endpoint'а**: endpoint + мережа + хмара + пошта + ідентичність у єдиній картині;
- **MDR (Managed DR)** — те саме, але **як послуга** (зовнішня команда моніторить за тебе; типово MSSP/провайдери SOC).

## DLP (Data Loss Prevention)

Не дає **чутливим даним покинути периметр**. Працює по станах даних:
- **Data at rest** (сховище) — захищає шифрування;
- **Data in transit** (мережа) — DLP ловить вихід назовні + TLS;
- **Data in use** (на endpoint'і) — DLP контролює копіювання/буфер/друк.

Канали, які стереже: **USB/зовнішні диски**, **мережа** (пошта, хмара, вебаплоад). Реакція: **блок** або **лог**. Варіанти: **endpoint-based** (агент) і **network-based**. Контрзахід проти **ексфільтрації** (остання фаза Kill Chain) та інсайдерського зливу.

## Керування endpoint'ами
- **MDM (Mobile Device Management)** — керування мобільними: політики, віддалене блокування/стирання, розділення робочого й особистого (BYOD).
- **UEM (Unified Endpoint Management)** — єдине керування **всіма** типами endpoint'ів (ПК + мобільні + IoT) з одного місця.
- **BYOD** — особисті пристрої на роботі: головний виклик — захистити корпоративні дані на пристрої, який **не контролюєш** (контейнеризація, умовний доступ, posture-перевірка через NAC).

## EPP vs EDR vs XDR (ключове)

| | **EPP** | **EDR** | **XDR** |
|---|---|---|---|
| Фокус | Protect (превентив) | Detect + Respond | Detect + Respond **крос-доменно** |
| Охоплення | один endpoint | endpoint + телеметрія | endpoint + мережа + хмара + пошта + identity |
| Дія | блокує відоме | ізолює хост, вбиває процес | корелює й реагує по всьому стеку |
| Передумова | не пустити загрозу | припускає, що вже прорвалось | повна видимість проти складних атак |

Разом покривають **Protect → Detect → Respond** на рівні пристрою. **EDR + SIEM** — основні інструменти моніторингу: SIEM зводить **логи** звідусіль, EDR дає глибоку **телеметрію з endpoint'ів + дію**; XDR частково зшиває обидва.
