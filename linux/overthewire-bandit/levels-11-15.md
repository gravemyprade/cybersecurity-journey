## Level 11 → 12 — ROT13

**Завдання:** пароль у `data.txt`, але всі латинські літери зсунуті на 13 позицій (ROT13).

**Хід думок:**
1. `cat data.txt` показав `Gur cnffjbeq vf ...` — схоже на «The password is», тільки зсунуте.
2. Розібрався з `tr`: він замінює символи першого набору на символи другого. Алфавіт ділиться навпіл по 13 літер (`a–m` і `n–z`), тож `a` стає `n`, а після `z` набір «загортається» на початок.
3. Спершу спробував замінити лише кілька літер (`tr "abc" "nop"`) і зрозумів, що без діапазонів довелося б перелічувати всі 52 літери.
4. `tr "A-Z a-z" "N-za-m N-ZA-M"` — у результаті з'явилися `^` і `]`. Діапазон `N-z` починався з великої літери й закінчувався малою, а між `Z` і `a` у таблиці кодування лежать спецсимволи — вони теж потрапили в набір.
5. `tr "A-Z a-z" "n-za-m N-ZA-M"` — вийшло `tHE PASSWORD IS ...`: зсув спрацював, але регістр перевернувся. Перший набір був «великі, потім малі», а другий — «малі, потім великі».
6. Вирівняв порядок в обох наборах:

```bash
cat data.txt | tr 'A-Za-z' 'N-ZA-Mn-za-m'
# The password is <пароль>
```

**Що вивчив:**
- `tr` замінює символи **за позицією**: перший символ першого набору → перший символ другого. Набори мають збігатися позиція в позицію.
- Діапазони рахуються за кодами символів, тому `N-z` захоплює не лише літери.
- ROT13, як і base64, — маскування, а не захист: розшифровується тим самим зсувом.

## Level 12 → 13 — багаторазово стиснутий файл

**Завдання:** `data.txt` — hexdump файлу, який багато разів стискали. Працювати радять у тимчасовій папці в `/tmp`.

**Хід думок:**
1. `mktemp -d qwe` → `too few X's in template`. Виявилось, що `mktemp` сам вигадує назву, а переданий текст сприймає як шаблон, у якому мають бути `XXX`. Без аргументів усе спрацювало.
2. Скопіював файл у робочу папку: `cp ~/data.txt .`
3. `file` на `data.txt` показав `ASCII text` — бо hexdump сам по собі текст (шістнадцятковий запис байтів). Спершу його треба перетворити назад на справжній файл.
4. У плані спершу був `xxd -r data.txt > data.txt`, але це зітре файл: оболонка очищає файл для `>` ще до запуску команди. Вихід має бути з іншою назвою:

```bash
mktemp -d
cd /tmp/tmp.XXXXXXXX
cp ~/data.txt .
xxd -r data.txt data
```

5. Далі — цикл, повторений кілька разів:

```bash
file data            # визначити тип
mv data data.gz      # дати розширення, якого чекає архіватор
gzip -d data.gz      # або bzip2 -d / tar -xf — залежно від типу
ls                   # подивитися, що вийшло
```

Послідовність шарів: gzip → bzip2 → gzip → tar → tar → bzip2 → tar → gzip → текст.

6. Після `tar -xf` чекав файл `data`, а з'явилися `data5.bin`, `data6.bin` — tar витягує файли з **їхніми власними** назвами. Тому після кожного кроку — `ls`.
7. Відкрив `data5.bin` через `cat` і серед нечитабельних символів побачив `ustar` і `BZh` — «магічні байти», за якими `file` і визначає tar та bzip2.
8. На останньому gzip `file` показав `original size ... 49`: «The password is » + 32 символи пароля + перенесення рядка. Тобто це останній шар.

**Що вивчив:**
- З незнайомим файлом спершу `file`, потім дія — не вгадувати за назвою.
- `mv` не перетворює файл, лише дає розширення, без якого `gzip`/`bzip2` відмовляються працювати.
- Магічні байти — «паспорт» файлу; розширення можна підробити, їх — ні.
- `>` у той самий файл, з якого читаєш, стирає його.

## Level 13 → 14 — вхід за SSH-ключем

**Завдання:** пароль лежить у `/etc/bandit_pass/bandit14` і доступний лише `bandit14`. Замість пароля дано приватний SSH-ключ.

**Хід думок:**
1. `ls` у домашній папці `bandit13` — файл `sshkey.private`.
2. Входити з сервера на нього ж (`localhost`) у Bandit заборонено, тому ключ треба забрати на свою машину командою `scp`.
3. Спершу вказав у `scp` користувача `bandit14` — але ключ лежить у домашній папці `bandit13`, і пароль є лише від нього. Забирати файл треба під тим користувачем, чий він:

```bash
# на своїй віртуалці
scp -P 2220 bandit13@bandit.labs.overthewire.org:sshkey.private .
```

4. `ssh -i sshkey.private bandit14@...` → `WARNING: UNPROTECTED PRIVATE KEY FILE! Permissions 0640 ... are too open`, і SSH попросив пароль. Приватний ключ, доступний групі, SSH вважає скомпрометованим і ігнорує.
5. Спершу думав, що права треба міняти на сервері, але SSH скаржився на **мою локальну копію** ключа — тож `chmod` потрібен на віртуалці:

```bash
chmod 600 sshkey.private
ssh -i sshkey.private bandit14@bandit.labs.overthewire.org -p 2220
cat /etc/bandit_pass/bandit14
```

**Що вивчив:**
- SSH-ключ — пара: публічний на сервері, приватний у тебе; хто має приватний, входить без пароля.
- `scp` копіює файли по SSH; порт — велика `-P`.
- Права числами: `4` — читати, `2` — писати, `1` — виконувати; три цифри — власник, група, інші. `600` — лише власник читає й пише.
- Повідомлення про помилки прямо кажуть, що не так.

## Level 14 → 15 — перше мережеве з'єднання

**Завдання:** надіслати пароль поточного рівня на порт 30000 на `localhost`, у відповідь прийде пароль наступного.

**Хід думок:**
1. Порт — це «двері» на сервері, за якими працює певна служба. `localhost` — той самий комп'ютер, на якому я зараз.
2. Потрібен клієнт, який відкриє з'єднання й дасть надіслати текст, — `nc` (netcat):

```bash
nc localhost 30000
# вставити пароль bandit14, Enter → Correct! <пароль>

# те саме одним рядком через pipe:
cat /etc/bandit_pass/bandit14 | nc localhost 30000
```

**Що вивчив:**
- Базова модель мережі: адреса — будинок, порт — двері, служба — той, хто слухає за ними.
- `nc` — найпростіший мережевий клієнт: підключитися, надіслати, отримати відповідь.
- Pipe працює й із мережею: вивід `cat` іде прямо в з'єднання.
- У SOC `nc` у логах підозрілого процесу — привід насторожитися: ним і перевіряють порти, і передають дані.

## Команди, вивчені за рівні 11–15

- `tr 'A-Za-z' 'N-ZA-Mn-za-m'` — заміна символів (ROT13)
- `mktemp -d` — тимчасова папка з випадковою назвою
- `cp файл .` — скопіювати в поточну папку
- `xxd -r hexdump вихід` — hexdump назад у файл
- `mv старе нове` — перейменувати
- `gzip -d`, `bzip2 -d`, `tar -xf` — розпакування
- `scp -P порт user@host:файл .` — забрати файл із сервера
- `ssh -i ключ user@host -p порт` — вхід за ключем
- `chmod 600 файл` — права лише для власника
- `nc host порт` — мережеве з'єднання

## Головні висновки

- Спершу визначити, з чим маєш справу (`file`, `ls`), потім діяти.
- Порядок і позиції мають значення: у наборах `tr`, у шляхах, у діапазонах.
- Уважно читати повідомлення програм — у них зазвичай уже є відповідь.
- Маскування (ROT13, base64, архіви в архівах) — не захист, а спосіб сховати від неуважного погляду.
