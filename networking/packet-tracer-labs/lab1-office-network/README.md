# Лаба 1 — Сегментована офісна мережа (VLAN, inter-VLAN routing, DHCP, DNS)

**Платформа:** Cisco Packet Tracer
**Теми:** сегментація на VLAN · 802.1Q trunking · router-on-a-stick · DHCP · DNS/HTTP
**Пристрої:** 1× маршрутизатор ISR 4331 · 1× комутатор Catalyst 2960 · 1× сервер · 7 кінцевих пристроїв

---

## 🎯 Мета

Зібрати робочу мережу малого офісу, поділену на три відділи, кожен — в окремій підмережі/VLAN, з автоматичною адресацією (DHCP) і внутрішнім сервером, доступним за іменем (DNS). Довести, що відділи логічно ізольовані на канальному рівні (L2), але маршрутизуються між собою через роутер, і що сервіси працюють за доменним іменем.

**Навіщо це з погляду захисту (blue team):** сегментація — це перша лінія оборони проти *бічного переміщення* (lateral movement). У плоскій мережі, зламавши хост у Бухгалтерії, атакувальник безкоштовно дістає IT і сервери. VLAN змушують увесь міжсегментний трафік іти через єдину маршрутизовану точку-вузол — саме там згодом ставлять ACL, моніторинг та інспекцію.

---

## 🧭 Топологія та адресація

Три відділи, кожен — окремий VLAN і підмережа /24. Один комутатор несе всі три VLAN; один транк-лінк до роутера забезпечує маршрутизацію між VLAN (router-on-a-stick).

📷 *`00-topology.png`*

| VLAN | Відділ | Підмережа | Шлюз | Статичні хости | Діапазон DHCP |
|------|--------|-----------|------|----------------|---------------|
| 10 | Accounting | 192.168.1.0/24 | 192.168.1.1 | Принтер 192.168.1.2 | .3 – .10 |
| 20 | Management | 192.168.2.0/24 | 192.168.2.1 | — | .2 – .10 |
| 30 | IT | 192.168.3.0/24 | 192.168.3.1 | Сервер 192.168.3.2 | .3 – .10 |

Маска: `255.255.255.0` скрізь. Приватний блок RFC 1918 (`192.168.0.0/16`) — внутрішня мережа, публічні адреси не використовуються.

**Рішення в дизайні:**
- **VLAN ID 10/20/30**, а не 1/2/3 — крок у 10 лишає місце для вставки майбутніх VLAN без перенумерації, а VLAN 1 лишається незайнятим (best practice з безпеки).
- **Шлюзи `.1`** кожної підмережі — по одному шлюзу *всередині кожної підмережі*, бо шлюз має бути в тій самій мережі, що й хости, які він обслуговує.
- **Статика** для інфраструктури (шлюзи, сервер, принтер); **DHCP** для ПК користувачів — відповідає реальній практиці й тримає інфраструктурні адреси передбачуваними.

**Карта портів (комутатор):**
- Fa0/1–3 → VLAN 10 (access) · Fa0/4–6 → VLAN 20 (access) · Fa0/7–9 → VLAN 30 (access)
- Gig0/1 → trunk (802.1Q) до роутера Gig0/0/0

## ⚙️ Налаштування

### Комутатор (рівень L2)
Створив три VLAN, призначив access-порти за відділами, а аплінк до роутера зробив транком 802.1Q. Access-порти несуть один нетегований VLAN (кінцеві пристрої); транк тегує кадри, щоб один кабель ніс усі три VLAN до роутера.

```
vlan 10 / name Accounting      (20 → Management, 30 → IT)
interface range fa0/1-3
 switchport mode access
 switchport access vlan 10     (повторити для .4-6 / vlan 20, .7-9 / vlan 30)
interface gigabitethernet0/1
 switchport mode trunk
```
*На 2960 `encapsulation dot1q` не потрібен — він підтримує лише dot1Q.*

### Маршрутизатор (рівень L3) — router-on-a-stick
Один фізичний інтерфейс, три субінтерфейси — по одному на VLAN — кожен тримає шлюз своєї підмережі. `encapsulation dot1Q <id>` каже субінтерфейсу, кадри якого VLAN обробляти; ID має збігатися з VLAN.

```
interface g0/0/0
 no shutdown
interface g0/0/0.10
 encapsulation dot1Q 10
 ip address 192.168.1.1 255.255.255.0   (.20 → .2.1, .30 → .3.1)
```
*На фізичному інтерфейсі IP немає — уся адресація живе на субінтерфейсах. Це і є суть ROAS.*

📷 *`02-router-subinterfaces-up.png`*

### DHCP (на роутері)
По одному пулу на VLAN. DHCP на Cisco-роутері роздає всю підмережу *мінус* виключені адреси — тому шлюз і статичні хости виключені, а решта роздається.

```
ip dhcp excluded-address 192.168.1.1 192.168.1.2   (шлюз + принтер)
ip dhcp excluded-address 192.168.2.1
ip dhcp excluded-address 192.168.3.1 192.168.3.2   (шлюз + сервер)

ip dhcp pool ACCOUNTING
 network 192.168.1.0 255.255.255.0
 default-router 192.168.1.1
 dns-server 192.168.3.2                            (повторити на кожен VLAN)
```

📷 *`03-router-dhcp-config.png`*

### Сервер (VLAN IT)
Статична `192.168.3.2`, шлюз `192.168.3.1`, DNS вказує сам на себе. Увімкнув **HTTP** (дефолтна сторінка) і **DNS** із записом A: `www.lab.local → 192.168.3.2`.

## 🔍 Спостереження (де реальність розійшлася з очікуванням)

1. **Перший пінг кожного нового потоку губиться (25% → 0%).** Перший ICMP-запит дає таймаут, далі летять Reply. Причина: роутер має резолвити MAC призначення через **ARP**, перш ніж переслати перший пакет; цей пакет губиться, поки ARP завершується. Повторний пінг — чисті 4/4. Не помилка, очікувана поведінка.

2. **TTL показує кількість пройдених роутерів.** Пінг до сервера (той самий VLAN) повернув `TTL=128`; пінг в інший VLAN — `TTL=127`. Кожен прохід через роутер зменшує TTL на одиницю — тож по TTL видно, чи відповідь прийшла з твого ж сегмента, чи була маршрутизована. Корисний сигнал у розслідуваннях.

3. **Діагностика DNS — локалізація поломки.** Браузер спершу видав `Host Name Unresolved`. Оскільки inter-VLAN пінги працювали, зв'язок було виключено, і поломку звужено до DNS. Корінна причина: запис A було набрано, але не збережено — я натиснув *Save/Remove* замість **Add**, тож таблиця записів була порожня і серверу не було чого резолвити. Кнопка **Add** виправила. *Висновок: локалізуй по рівнях — перевір по IP vs по імені, щоб відділити зв'язок від резолвінгу імен.*

## 🧾 Висновок

Один фізичний комутатор і роутер дають три логічно ізольовані мережі, які маршрутизуються через одну контрольовану точку-вузол, з автоматичною адресацією та резолвінгом імен. Найважча частина — router-on-a-stick + узгоджене тегування VLAN — це фундамент, на якому будується будь-яка сегментована корпоративна мережа.
